# 异常状态与冲突

本技能不建立多人协作、分支合并或远程同步流程。

- 开始操作前若已有冲突、未完成的 merge/rebase/cherry-pick/revert 或分离 HEAD，停止 Git 写操作，向主 Agent 报告状态。不要擅自中止用户原有操作或清理工作区。
- 本次撤销或重做若产生冲突，说明受影响文件并执行 `git revert --abort`，按仓库既有换行约定核对文档内容、索引和历史已恢复，然后向主 Agent 报告；不自动合并文档或选择 ours/theirs。已有仓库若仅发生换行转换，如实说明，不为此临时修改配置。
- 图片、视频无需 Git 冲突处理，因为它们不受追踪。文档型二进制发生冲突时，不自动合并；由主 Agent 明确要取回的版本后按文件快照恢复。
- 操作失败不代表用户必须放弃已有工作。保留原有改动、暂存状态及历史，说明未完成的请求即可。
