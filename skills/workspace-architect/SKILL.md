# 工作区规划与归档

目录与文件名帮助 Agent 快速定位信息；读写边界保护事实来源；可变契约、草稿与已验收交付物各有位置。结构从项目需要推导，宁简勿全，不照抄全套目录。

## 只读约定

- 本技能中的“只读”仅通过 AGENTS.md 和相关规范文档约束 Agent 行为。不得修改用户本机文件或文件夹的系统权限、访问控制、所有权、权限继承或只读属性。
- 制定规范时提醒用户一次：“如果需要绝对的只读权限控制，请自行设置相应的目录权限。”本技能不代为设置。

## 路由与对齐

- 无规范，或要建立、调整规范：任务一。已有规范，需要整理文件：任务二。
- 无规范却请求归档：先任务一，再接着任务二；每阶段只处理该阶段的确认，不把初始化当成归档完成。
- 动笔前明确目标、已有输入、最终交付；优先从现有文件找答案，每轮只问最影响结构的问题。只为真实需求建目录，只为反复产生或易混淆的文件定规则。
- 复用本次对话已有确认。用户已明确授权按给定方案落地，或授权你决定命名等常规细节时，执行相应部分；仍需用户选择的关键分类、读写约定或生效版本先给出具体方案再确认。

## 任务一：制定规范

**终点**：已建立获授权的目录骨架、精短 AGENTS.md 和 `.agents/workspace_conventions.md`；不移动现有文件，不开始业务正文、数据清洗或内容总结。

已确认目录若无法容纳确需保留的探索草稿或媒体旧版，不用状态前缀将它们混放进当前契约目录，也不擅自扩建。先完成可执行部分，在规范中将该能力标为待补齐；实际需要时提出最小分区增补方案供确认。没有该需求时不预建目录；当前计划与需求仍在文档区原文件上迭代。

按实际需求在下钻规范中约定：
- **事实与契约**：原始 Brief、研报和原文归只读参考区；计划、需求与约束归可变文档区。正式需求变更同步到当前契约，不能只留在聊天或记忆中。
- **数据**：存在结构化数据时区分只读 raw 与可写 processed。清洗结果另存并保留来源；计算交给脚本和工具，不在整理目录时直接清洗或心算。
- **探索与交付**：未验收草稿、试验与正式规范隔离；交付区只放已验收成品。脚本按需独立保存。
- **记忆与笔记**：需要持续协作时，记忆提纯为决策、教训、下一步；Notebook 记录临时 TODO、发现、进度与恢复入口。原始聊天留作参考；正式规则归文档，记忆不得取代它。
- **身份与外脑**：只有存在多角色或跨项目复用需求时，才设置角色入口或知识、经验、工作流的复用位置；不强制创建空目录或链接外部资产。
- **命名与生效版本**：文件名概括内容；目录已有类型信息时省略 ref/doc 等重复前缀；日志、会议等用 YYYY-MM-DD 开头；用 `_` 或 `-` 代替空格。单个逻辑文档只保留一份当前生效文件，文件名稳定；文本等可编辑文档在当前文件上迭代，本技能不管理其历史版本。只有图片、视频、音频等媒体二进制文件确需保留旧版时，才考虑按需使用 archive；不得因此移动或改写只读原始素材。不同日期的独立周报不算同一文档的历史版本。验收依据不明时不能用“最新”、版本号或时间戳擅自定版。

AGENTS.md 使用下方模板；详细规则放下钻。已有 AGENTS.md 在原文上合并，保留业务红线及有效导航；更新时同步相关入口，不留下失效路径。

**验收**：每个目录有需求依据，每类输入与交付有去处；只读区域明确；下钻路径存在。未参与对话的 Agent 只读入口就知道目标、找什么、去哪找、哪些不能改，以及何时下钻。

## 任务二：归档文件

**终点**：获确认的文件按规范归位；内容不变，路径、导航和操作记录一致。

- 只移动和重命名，不改内容、不合并、不删除。疑似重复、用途不明或生效依据不足的文件留在原位，列出已知信息与需要的决定。
- 执行前提交“原路径 → 新路径”映射；已逐项确认的映射直接执行，未确认部分等待确认。检查同名目标、路径范围与已有引用，不能覆盖目标或把文件移到项目外。
- 只读区的现有资料不因整理而改写、删除、移动或重命名。收件箱材料可按确认映射首次归入，归入后遵守只读规则。用户明确改变已有边界时先指出受影响的引用与恢复方式，并同步规范；不要把项目约定说成系统强制权限。
- 规范装不下某类文件时，返回任务一修订对应条目；保留后续归档目标。
- 按映射逐项核对实际路径和文件数量，将实际映射与未处理事项保存在项目内。若需改动引用或索引，单独说明并记录这些元数据变更，不改写原始材料。

**验收**：已执行映射逐项核对，无丢失、覆盖、内容变化或失效入口；未处理文件原因明确；可追溯。部分完成时清楚列出余项，不宣称全部完成。

## AGENTS.md 模板

```markdown
# <项目名>
<一句话目标与最终交付>

## 目录导航
| 目录 | 放什么 | 读写约定 |
|---|---|---|
| <实际目录> | <用途；区分原始/衍生、当前/草稿> | <只读 / 可改> |

## 红线
- <实际只读区> 的已有材料只能引用，不改写、覆盖、删除、移动或重命名。
- 只读仅为文档约定，不得修改本机文件或文件夹的系统权限、访问控制、所有权、权限继承或只读属性；如需绝对的只读权限控制，请用户自行设置相应目录权限。
- 当前规范以 <实际生效文档或其索引> 为准；草稿、聊天与旧版本不作为生效契约。

## 新建、重命名或移动文件前
- 先读 `.agents/workspace_conventions.md`，遵守分类、命名、版本与归档规则。
```

不存在只读材料或生效文档时按事实写明，不填虚构路径。总入口保持精短，详细角色、流程与经验按触发条件链接下钻。

## 参考范例（按需选取）

```text
my-project/
├── AGENTS.md
├── .agents/               # 下钻规范；按需放角色与工作流
├── 00_inbox/              # 待分类输入
├── 01_references/         # 只读事实来源
├── 02_docs/               # 当前可变契约
├── 03_data/
│   ├── raw/               # 只读原始数据
│   └── processed/         # 可写衍生数据
├── 04_experiments/        # 未验收草稿与试验
├── 05_scripts/            # 自动化工具
├── 06_memory/             # 提纯后的决策、教训、下一步
├── 07_deliverables/       # 已验收交付
├── 08_notebook/           # 临时进度与恢复入口
└── archive/               # 按需保存图片、视频、音频等媒体二进制文件旧版
```
